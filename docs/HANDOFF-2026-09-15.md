## 4. 关键决策与理由

只记**为什么**，是什么去看对应文档。

| 决策 | 理由 |
|---|---|
| 单个 v0.2.0 拆成 **0.2.0 / 0.3.0 / 0.4.0** 三版 | release 的单位是「装上能看出差别的东西」，不是「一批做完的活」。原 A–F 六组按工作性质分，A 组（文档）产物零变化、F 组（验证发布）是每版都要做的动作，都不能独立成版 |
| 只切三版而不是六版 | 每个 release 要双平台打包 + 实机验证，切太细验证成本线性上升 |
| **0.2.0 刻意不依赖 LLM 网关** | 网关是单台自建实例，刚宕了五个月还会再宕。这条设计让「看得见的桌宠」在网关不可用时照样能做完能发 |
| 新增 **G1**（引导硬门禁改软门禁） | `ConnectionStep.tsx:53` 要求连接测试通过才能进下一步，网关一挂新用户被永久挡在门外，连桌宠都看不到。网关恢复后该项从「阻塞验收」降为「健壮性修复」，但建议留在 0.2.0——它正是过去五个月的教训 |
| 取消「实现必须经 `codex exec`」 | 本地 Codex CLI 0.136.0 跑不起来，而该约束让 B/C/E 三组一行代码都写不了。五阶段流程保留，只换执行者 |
| 模型选 **M2.7-highspeed** 而非 M2-her | M2-her 是角色扮演专用、更合适，但**国际站没有上架**（实测目录只有 M3/M2.x 系列）。M2.7-highspeed 是现有目录里的务实选择：2.x 线最新 + 100 tps。延迟对桌宠是产品特性，同能力一律选 highspeed |
| 日志根目录用 `getDataPath()` 而非 `app.getPath('userData')` | 与 `getDBPath()` 的分环境约定一致，开发态日志就在 `<repo>/data/logs` 手边，不用去系统目录翻。顺带给死代码 `getDataPath()` 第一个调用方 |
| `<think>` 剥离必须**早于** OOC 检测 | 不只是显示问题：OOC 模式里的 `/as an? (...|assistant)/i` 会匹配思维链中的 `as an assistant`，一旦命中触发最多 2 次重试，同一条消息付三遍钱 |
| `EXECUTION_TRACKER.md` 为唯一状态源 | 见 §5.1 |

## 5. 已经踩过的坑

### 5.1 `DONE` 不带提交号 = 没有可验证的锚点

A 组做完后 tracker 标了 `DONE`，Evidence 只写「review 通过」**没有提交号**，而改动尚未提交。
于是另一个 worktree（停在 `3081f80`）上的核验必然看到旧内容并判为「未完成」——**双方都没错，结论相反**。

现在规则是硬的：`REVIEW` 必须有提交号，`DONE` 必须有四要素（命令/结果/提交号/日期）。
详见 [`v0.2.0/PREFLIGHT.md`](./v0.2.0/PREFLIGHT.md) §4/§6。

### 5.2 集成测试的 baseUrl 默认值会静默打错服务器

`tests/integration/helpers.ts` 原本有一个写死的默认 baseUrl，指向已停用的旧主机；
而 skip 判定只看 `CPA_API_KEY`，**漏设 baseUrl 不会 skip，会静默打到错误的服务器**。
已改为三个变量全必填、无默认值。**不要再给它加默认值。**

### 5.3 `.env.example` 是受跟踪文件

真实密钥曾被填进 `.env.example`（只停留在工作树，未进任何提交）。
现在第一行有方框警告。**正确做法是 `cp .env.example .env.local` 后填 `.env.local`**。
另外：`.env.local` 已存在时**不要再执行那句 `cp`**——会把填好的值冲掉（已经发生过一次）。

### 5.4 Grace 用 fish，不要给 bash-ism

`set -a; source .env.local; set +a` 在 fish 下直接报错。
现在 `cpa_probe.mjs` 与 jest（`tests/setup-env.js`）**各自读取 `.env.local`**，
零依赖、不挑 shell。写文档时别再给需要 source 的命令。

### 5.5 两层密钥容易混

```
Soul Link ──CPA_API_KEY──▶ CPA ──MiniMax key──▶ MiniMax
              ↑ CPA config.yaml 顶层 api-keys    ↑ CPA 供应商条目里
```
`CPA_API_KEY` 是 Grace 自己给网关定的门禁，不是从 MiniMax 领的。

### 5.6 「测试通过」不等于「功能可用」

`compression.test.ts` 跑 27 秒、显示 PASS、文件名叫 compression——但它只发 4 条消息，
而 `COMPRESSION_THRESHOLD = 30`，**压缩逻辑一次都没执行过**。F5 目前零覆盖。
读到绿色先确认它到底测了什么。

### 5.7 git 锁文件

在这个环境里 git 提交后偶尔残留 `.git/index.lock` / `HEAD.lock` / `tmp_obj_*`，
导致后续 git 写操作全部失败。删掉即可恢复（需要删除权限）。

### 6.1 这个 Linux VM 能做什么、不能做什么

会话通过一个挂载了仓库目录的 Linux VM 操作代码。实测边界：

| 能 | 不能 |
|---|---|
| `tsc` 三份配置、`jest`、`build:main`（纯 TS/JS） | **`build:renderer`** —— `node_modules` 装于 macOS，Linux 侧缺 `@rollup/rollup-linux-*` 原生二进制 |
| git 提交、HTTPS 读远端（`git ls-remote` 可用） | **git push** —— VM 内无任何凭据：无 `~/.ssh`、无 credential helper、无 `GH_TOKEN`、无 `gh` CLI |
| 读写仓库内文件 | 访问 CPA 网关（出网白名单拦截）、跑 Electron GUI |

**结论：凡是需要真机的（GUI 验收、打包、推送、连网关），都得 Grace 在 macOS 上做。**
